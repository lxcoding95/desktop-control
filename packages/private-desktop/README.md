# Owner-private Windows desktop helper

Active control additionally shows four subtle, click-through blue gradient edges on each monitor present at activation. They are native nonactivating layered windows, scaled by per-monitor window DPI, and are removed on EOF, Esc, partial startup failure or helper exit. A monitor settings change stops control rather than retaining stale edge geometry. See [the indicator implementation and actual Windows evidence](../../docs/integrations/desktop-indicator.md). One physical monitor was tested; additional monitor/DPI cases are synthetic until separately demonstrated.

This package is a high-trust, full interactive desktop boundary. It is not an OS sandbox. No general shell, arbitrary executable, file-path action, UAC approval, or permission-reset action is exposed by its native JSON protocol.

Build with `node packages/private-desktop/controller.mjs --build`; the fixed Windows Framework compiler writes only ignored `dist/private-desktop/desktop-controller.exe`. Test wrapper boundaries with `node --test packages/private-desktop/test/*.test.mjs`. No external runtime dependencies are added.

`createDesktopController({ authorize, onEmergencyStop, protectedProcessIds })` exposes `start`, `screenshot`, `move({x,y})`, `click({button,x?,y?})`, `key({key})`, `typeText({text})`, and `stop`. Authorization must reject on denial and freshly enforce the host policy for `desktop.read` or `desktop.input`. The caller must not expose optional `helperPath` or `spawnHelper` injection remotely. They are trusted build/test seams. Unknown configuration keys are rejected so a misspelled test transport cannot silently fall back to the real desktop. `start` is required before input; a read-only screenshot does not activate the cursor/banner. A stopped wrapper must be recreated only after actual local re-enable and host authorization.

The normal-user helper requires Windows PerMonitorV2 DPI awareness (fails closed if unavailable), interactive medium integrity, refuses elevated targets when known, and denies unknown/inaccessible input targets. Protected process IDs and `DesktopControlPrivateSettings` top-level window class prefixes deny input. The host must protect every permission UI process ID. Screenshot access remains full desktop read access and may include permission UI. Target checking before SendInput is best effort: foreground windows and pointer positions can change concurrently. This does not provide process isolation or prevent all indirect manipulation of settings via the broader OS.

Active input shows `ChatGPT controls your computer | Esc to stop` and temporarily replaces common system cursors with an original black arrow. The hook responds to Esc, stops subsequent input, writes the fixed `%USERPROFILE%/.desktop-control-private/desktop-stop` sentinel, restores the configured cursor scheme, and closes the helper. The helper never clears the sentinel or grants itself permission. The host must create/protect that directory beforehand and revoke the desktop grant through `onEmergencyStop`. Failure to write the sentinel still stops this process, but durable revocation also depends on the host callback and protected storage. All ordinary input batches pair key/button down/up; no held-key RPC exists. Partial Windows SendInput acceptance triggers best-effort matching key/button release and an emergency stop. OS input failures can still prevent delivery; this is not a guarantee that every OS failure can be recovered.

Cursor replacement uses the 13 IDs documented for [SetSystemCursor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setsystemcursor). Unsupported legacy OCR_SIZE/OCR_ICON and undocumented OCR_HELP replacements are excluded. Partial cursor failures restore the scheme and dispose unconsumed handles. Start failures clean initialized hooks/cursor state and exit even before Active was set. Private reflection fields retain only a numeric failure ID/error for native contract tests; normal MCP output remains CURSOR_FAILED. The earlier actual failure did not record its exact ID, so it cannot be retrospectively attributed to a particular ID as proven fact.

A separate normal-user watchdog waits for helper exit and restores the cursor scheme, including forced termination. Parent stdio closure requests a normal stop. The watchdog cannot recover if it is killed alongside the helper, the user session ends unexpectedly, or OS APIs fail. It never edits the cursor registry. Runtime cursor changes may affect other applications in the same interactive user session. Do not claim emergency-stop or forced-kill restoration acceptance until real fixture checks have observed those paths.

Limits: PNG output 4 MiB, virtual-screen pixel budget 32 million, UTF-8 text 8 KiB, incoming native protocol lines 16 Ki characters, fixed key names, serialized requests, host request timeout up to 30 seconds. Native errors return fixed codes. Screenshots contain private pixels and must only be requested under explicit host read authorization; tests must not print/store them. Linux support and secure-desktop/UAC interaction are not implemented.

Current noninteractive verification: native source compiles; 15 wrapper boundary/lifecycle tests and 6 native reflection tests pass on Windows (21 passed; the separate opt-in interactive fixture is explicitly skipped in default discovery). Reflection tests instantiate invisible banner/edge forms and inspect nonactivation/click-through flags, negative-coordinate/DPI geometry and blue alpha gradients, and invoke pure release-event construction, cursor replacement/rollback delegates and partial-start cleanup delegates; they do not enter the native Main function or call input, screenshot or cursor APIs. The banner uses ShowWithoutActivation and WS_EX_NOACTIVATE so displaying status does not intentionally take keyboard focus. Transport errors, malformed/oversized unterminated output, process startup failure and authorization denial after activation terminate this controller instead of silently retrying. Stop closes native stdin and has a bounded force-termination fallback. A coordinated actual Windows rerun at 2026-10-25T12:15Z passed the owned-window input, visible banner/four-edge indicator, cursor-change/restore, EOF, forced-helper-exit/watchdog and injected-Esc durable-stop paths, with indicator cleanup confirmed on one actual monitor. Physical hardware Esc and broader desktop compatibility remain separate acceptance gates.


Authorization is fresh per queued action and before each text chunk of at most 32 Unicode code points. Active input sessions additionally recheck desktop.input after each 250 ms idle polling interval; denial terminates the helper, and a hanging policy callback has a 1 second monitor deadline. Polling and OS scheduling are not instantaneous revocation. Native batches already admitted to Windows cannot be recalled; native Esc checks and per-character stop-file checks bound subsequent work. Polls stop on EOF, explicit stop, native failure and emergency stop. The fixed private-settings process name, protected process IDs and configured class prefix are denied input targets, including settings opened manually. The actual owned OS fixture verifies the input/stop/lifecycle subset; protected settings targets, arbitrary applications, multi-monitor/DPI contention and final host integration remain separate acceptance gates.
