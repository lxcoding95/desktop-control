# Desktop-Control-Browser

This experimental component defaults to its **own separately installed browser runtime** and persistent profile, not the user's Edge or default profile. Playwright Core **1.64.1** (Apache-2.0) pins Chromium revision **1248**, version **156.0.8078.4**, labeled **Chrome for Testing** in the actual SDK manifest. This is an upstream Chromium-based binary, **not a new Desktop Control browser fork**. Chromium's open-source engine licensing does not by itself prove redistribution permission for every branded binary/component. Original binary license/notice and authenticity acceptance remain separate gates; no public browser redistribution is performed here.

`createBrowserController({ authorize, profileDirectory?, channel?, allowPrivateOrigins?, onEmergencyStop? })` provides `start`, `navigate({url})`, `snapshot`, `click({role,name}|{selector})`, `fill({...target,value})`, `press({...target,key})`, `scroll({deltaY})`, `screenshot`, `tabs`, `newTab({url})`, `selectTab({tabId})`, `closeTab({tabId})` and `stop`. The host-managed default profile is `.desktop-control-private/browser-profile`; the host must validate and protect it before construction. Alternate profile paths, private-origin access and the explicit `channel: 'msedge'` fixture fallback are trusted constructor settings, never MCP arguments. No implicit Edge fallback exists. Chromium's process sandbox is enabled; missing platform requirements fail closed instead of adding administrator dependencies automatically.

## Dedicated runtime installation and receipt

After the native identity/policy helpers have been built, the trusted local command `node packages/private-browser/runtime.mjs install` invokes only this pinned SDK's CLI: `install chromium --no-shell --no-remove --no-progress`. It installs into protected per-user `.desktop-control-private/browser-runtime`, enables no grants, does not install OS packages or request elevation, and retains old runtimes for recovery. It strips Playwright download-host/path/platform overrides and Node injection variables from the installer environment. Existing proxy/CA settings are retained. The executable must be the fixed revision/platform path, with regular-file/no-symlink ancestry checks and native host directory validation.

`node packages/private-browser/runtime.mjs status` returns sanitized SDK/revision/browser/platform status and a local executable SHA256. Successful installation writes `install-receipt.json` in the protected runtime directory. The hash proves the measured local bytes; it is **not an independently verified upstream archive signature**. Receipts explicitly keep `upstreamSignatureVerified` and `redistributionAccepted` false. The runtime is not embedded in the plugin ZIP and has no autonomous updater yet. Only Windows/Linux x64 paths are implemented; installation is not proof that Linux graphical dependencies or permissions are available.

## Separate AI page cursor

An original black SVG arrow and `Desktop-Control-Browser | ChatGPT controls your browser | Esc to stop` advisory are injected into the page. Automation moves the page-local AI indicator before click/fill/press/scroll through fixed Playwright code. No OS mouse injection or human `mousemove` listener is used. Independent DOM mouse movement leaves the AI indicator position unchanged. This is **not** a second physical Windows/Linux mouse. Browser chrome, another program and the secure desktop are outside this indicator. Desktop Control uses the host assistant; it creates no separate AI agent.

Page Esc can call only the fixed stop binding: it closes the context, invalidates queued input and notifies the optional trusted `onEmergencyStop` host callback. It cannot grant or re-enable permissions. Durable policy revocation requires that host callback; context stop alone is not a new grant. Page DOM and bindings can be altered or invoked by page code, so the advisory is **not trusted security UI** and cannot replace native permission consent or desktop emergency-stop enforcement.

The host callback receives `browser.read` or `browser.interact` and the destination origin when known. It must return `{ expiresAt, allowedOrigins }` from a fresh, native identity-bound protected host grant, or reject. Origins must be exact canonical HTTP(S) origins (maximum 20), with no credentials or path. Private/reserved literal addresses and localhost names are denied by default; `allowPrivateOrigins` exists only for a separately approved host configuration or isolated loopback fixtures. It is not a remote tool argument. No method provisions a grant.

Requests are serialized; grants are rechecked for each action, routed resource request and once per second while idle. Denial or expiry closes the browser. `stop` bypasses the action queue, closes the context to interrupt an active operation and invalidates previously queued requests. Context closure also clears its timer, active page and tab IDs and invalidates the old action generation. It stays available without a grant. An explicit subsequent `start` requires fresh authorization and creates a new context after closure. Native process/profile cleanup can still fail; startup errors remain redacted and fail closed. An accepted OS/browser action cannot be undone if revocation happens after dispatch. The host should call `stop` on MCP cancellation or shutdown.

## Boundaries and unresolved acceptance

- HTTP **redirects are blocked**, including same-origin redirects. A real Edge regression demonstrated that `route.continue` follows redirect hops without invoking the route handler for each hop. Checking only the first redirect also failed for a two-hop chain. This implementation fetches one response with `maxRedirects: 0` and aborts redirect responses. Secure login/redirect compatibility remains **OPEN**.
- Service workers and WebSockets are blocked, dialogs dismissed and downloads cancelled. Upload, arbitrary JavaScript, CDP, browser preference and permission-grant tools are absent. Per-origin permission is not per-account or per-critical-action consent. Account/security/payment/message/delete controls are **NOT IMPLEMENTED**; do not use this component for those actions before the host adds and tests those boundaries.
- Playwright routing is **not an OS network sandbox**. Hostname DNS/rebinding, browser background traffic, browser extensions/native browser behavior and arbitrary same-origin application requests are not proven contained. Persisted browser startup state can run before page routing is installed. An OS-enforced egress boundary is required before claiming complete network isolation. Do not load untrusted existing profiles or call this a general SSRF firewall.
- At most eight tracked tabs, five-second action/route timeouts, 32 KiB returned snapshot, 4 MiB returned PNG, 8 KiB fill input, 512-character selectors and a fixed key vocabulary. Browser/response memory itself is not hard-limited by this wrapper. Errors omit URLs, local paths, cookies and raw browser diagnostics. Snapshots and screenshots may contain private page content by design and require read permission.
- The controller does not implement a black system cursor, desktop banner, a second independent OS cursor, secure-desktop interaction or a permissions dashboard. Those are separate host/desktop integration gates. There is no verified Linux headed-browser matrix yet.

## Verification

`node --test packages/private-browser/test/*.test.mjs` runs policy and installer tests and explicitly skips visible fixtures by default. After coordinating visible windows, `DC_BROWSER_INTERACTIVE_TEST=1` enables the real Windows browser test with temporary isolated profile and two ephemeral loopback HTTP fixtures. Also set `DC_BROWSER_MANAGED_TEST=1` for the dedicated installed runtime; otherwise this explicitly coordinated test uses the trusted Edge fallback. It checks navigation, semantic fill/click, accessibility snapshot, screenshot response (pixels are never logged or stored), tabs, stop during a pending locator, revoked authorization and a two-hop redirect with **zero foreign HTTP hits**. It also kills only the uniquely identified browser process for its own random temporary profile, waits for that native process to exit, rejects stale queued input and proves fresh restart both after an active-operation crash and an idle crash. Last-tab closure is checked separately. The second owned-page fixture checks that a real trusted DOM mousemove without the AI update event leaves the AI cursor unchanged, then checks the Esc stop binding. Neither fixture injects OS mouse input into normal applications or uses a real account/default browser profile. Temporary profiles are removed after closure.

The private controller is not yet accepted as a production host integration merely because its fixture passes. Root integration must supply protected grants, critical-action consent, lifecycle ownership, packaging/licenses and independent review.
