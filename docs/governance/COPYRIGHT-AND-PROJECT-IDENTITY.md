## Keep private material out of public source

The public repository, its unmerged branches, Git history, issues, CI logs and release artifacts are cloneable. They must contain **no** production signing private keys, personal Windows/Linux usernames or home paths, device identities, sensitive browser profiles/cookies, account credentials, private license secrets, or confidential strategy. See [Public Information Policy](PUBLIC-INFORMATION-POLICY.md) and [Security](../../SECURITY.md). Secrets belong in an OS-protected local vault; public source should contain only reusable logic and redacted examples.

Previously published blobs and clones are not made private by deleting a file later. If a real credential leaked, revoke/rotate first, and handle public Git history under a separately reviewed incident plan. Do not force-push/rewrite protected history as routine cleanup.
