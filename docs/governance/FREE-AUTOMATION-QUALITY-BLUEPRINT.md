# Free CI, Privacy and Repository Maintenance Blueprint

**Public proposal — 2026-10-24.** Tracking: [#27](https://github.com/lxcoding95/desktop-control/issues/27). **Nothing on this branch is activated on `main`**: no CI, Actions, updater, scanner schedule, public release, licence service, or automatic merging. Tests must be attributed to their exact code/host and cannot guarantee zero defects or secrets.

## Execution and trust levels

1. **Before any public GitHub write:** use `node tools/governance/public-guard.mjs --json` to review all tracked + untracked (non-ignored) files, including real user paths, emails, private IPs/SIDs, typical tokens/keys and non-text files. This tool emits **file, category, line**, never the matched string. `node --test tools/governance/public-guard.test.mjs` is a zero-dependency synthetic regression suite. A `PASS-LIMITED` result is **not** a clean full-history report. All actual found values must remain outside public tickets/logs.
2. **Before any merge:** scan **all reachable branches, tags and Git history** independently with a pinned stable, MIT-licensed [Betterleaks](https://github.com/betterleaks/betterleaks) binary (original Gitleaks maintainer; verify release provenance/checksum for Windows/Linux). Compare with [Gitleaks](https://github.com/gitleaks/gitleaks) where helpful. The Betterleaks 2.x candidates are prereleases as of this review; don't silently promote incompatible release candidates. The proprietary [Gitleaks-Action](https://github.com/gitleaks/gitleaks-action) v2 license is not interchangeable with the MIT CLI. [TruffleHog](https://github.com/trufflesecurity/trufflehog) v3 is AGPL-3; assess separately before code reuse.
3. **Existing history exposure:** scan noncurrent commits, logs, attachment/artifact metadata and author identity. A public GitHub repo exposes its owner login, public commit authors and any publicly published history: scanning alone cannot make these anonymous. On a real secret exposure, **revoke/rotate first**, privately triage remediation, and never unilaterally force-push protected `main`.
4. **Free native GitHub layer:** Secret Scanning and Push Protection are available free for public repositories; settings are verified/activated by Alex through [security settings](https://github.com/lxcoding95/desktop-control/settings/security_analysis). Their detection is pattern-dependent, not a guarantee. Never paste findings, tokens, private home paths, IPs or device identifiers into GitHub issues or ChatGPT messages.
5. **Maintenance PRs, no auto-merge:** [Dependabot](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/secure-your-dependencies/configure-version-updates) `.github/dependabot.yml` proposes weekly npm updates (at most five open; development minor/patch grouped). `main` currently has no npm runtime manifest; effective npm updates require corresponding product code to be merged separately. Security and major/ABI-breaking changes need independent review, actual regression and license checks. No Actions ecosystem updater until immutable SHA policy is established.
6. **SAST, CI and hosted runners:** OSS [actionlint](https://github.com/rhysd/actionlint) (MIT), [zizmor](https://github.com/zizmorcore/zizmor) (MIT), [OSV Scanner](https://github.com/google/osv-scanner), [OpenSSF Scorecard](https://scorecard.dev/) and public-repo [CodeQL default setup](https://docs.github.com/en/code-security/how-tos/find-and-fix-code-vulnerabilities/configure-code-scanning/configure-code-scanning) are evaluated as complementary tools. Verify each version, license and distribution checksum first. Public standard GitHub-hosted Actions runners are free under GitHub terms; **no always-on Alex PC needed**.
7. **SEC-GATE-001 first:** no GitHub Actions workflow or CodeQL default setup activation before all external `uses:` actions are verified full 40-character commit-SHA pinned and Alex confirms [required GitHub Actions policy](https://github.com/lxcoding95/desktop-control/settings/actions) is enforced. Use read-only permissions by default, limited runner time, safe fork PR boundaries, no untrusted `pull_request_target` execution or shared credentials in untrusted builds.
8. **Evidence chain:** issue → product milestone Mnn (never historic S01–S06) → exact tested branch/head → checks/OS/versions/results → independent reviewer → squash merge → changelog/docs/release and rollback. Use [M01–M06/M07+ migration #25](https://github.com/lxcoding95/desktop-control/issues/25); keep Project-v2 boards private. Automated drift checks must be truly deployed and verified before being labelled active.

## What actually passed

The **portable public guard** was written and checked locally on Linux Node `v22.16.0` with six synthetic cases: clean Git file, fake Windows path and email redaction, fake GitHub token redaction, binary fail-closed, non-Git failure exit 2, and hashed sensitive filenames. `node --check` and `node --test` passed **6/6**. These are self-contained fixture tests, **not** a run against full S02 Git history, a Windows test, an independent code review or an enabled GitHub CI run.

## Exact open gates

- **Privacy blocker:** sampled public S02 Windows evidence includes local user home paths; no actual credential exposure has been established, and **full contents + history scan remains unverified**. Run stable Betterleaks/Gitleaks and privately review findings before PR #22 acceptance.
- **Quality blocker:** run public guard, Dependabot schema/API validation, Node tests and toolchain audit against an actual clean Windows/Linux checkout and independently review negative/fuzz edge cases.
- **Owner-only settings:** [Security toggles](https://github.com/lxcoding95/desktop-control/settings/security_analysis) (Secret Scanning/Push Protection, Dependabot alerts) and [Actions SHA policy](https://github.com/lxcoding95/desktop-control/settings/actions) require Alex's explicit UI readback; **do not activate Actions during SEC-GATE-001**.
- **GitHub milestones:** create product M01–M06 via [GitHub Milestones](https://github.com/lxcoding95/desktop-control/milestones) once the existing historical membership mapping is inventoried; private Project v2 metadata remains owner/UI-only.
- No permanent secret-free guarantee is possible from any finite scanner suite. A successful scan is a **bounded, versioned proof of what was examined**, not proof of all future code.
