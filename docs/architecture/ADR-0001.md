# ADR-0001: MCP tooling with a local desktop execution bridge

- Status: **Proposed**
- Date: 2026-10-21
- Deciders: repository maintainer (approval pending)

## Context

The target experience is a ChatGPT-installable plugin similar in ease of use to Desktop Commander, while remaining usable from other MCP clients. The user requested full Windows/Linux desktop control, but without creating a second AI agent.

## Decision (proposed)

Separate AI-client orchestration and MCP tool schemas from the local privileged desktop execution boundary. Favor a local-first read-only vertical slice before remote routing. The future gateway forwards authorized requests rather than executing privileged OS actions itself.

## Alternatives

- A wholly local stdio MCP server: simplest for desktop clients, but may not be accessible from web-only ChatGPT sessions.
- A hosted-only remote agent: simplifies browser connections, but creates data and trust concentration.
- A remote MCP gateway plus local bridge: supports web clients and self-hosting at the cost of authentication, device lifecycle and transport complexity.

## Consequences

A complete design needs replay protection, device revocation, scoped credentials, deliberate privilege elevation, offline handling, cancellation and traceable auditing. Deployment claims depend on measured tests.

## Validation needed

- Verify current MCP protocol and the target client's installation package requirements.
- Implement and test one read-only command in an isolated test machine.
- Exercise disconnected-device, expired-token, parallel-request and cancellation cases.
- Prove Windows and Linux packaging assumptions with actual installations.

This proposal is **not accepted** until feasibility and security criteria pass.
